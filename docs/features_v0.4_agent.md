# v0.4：受限只读 Agent 执行循环

日期：2026-10-28。沿用v0.3订单业务服务，新增持久化执行循环、本地模型适配器、网页步骤面板和独立评测入口。

本地模型由用户后续部署，URL、Key和模型名目前留空，真实调用关闭。代码和模拟协议/脚本决策回归已经验收；尚没有真实本地模型的任务成绩。离线规则不负责模拟条件判断。

## 使用入口与配置

网页助手新增“助手执行模式”：

- 单步操作：保留原来的助手接口和受确认保护的字段修改。
- 只读Agent：仅能查询、导出；运行中展示决策次数、工具次数、实际观察、停点、错误和真实文件。

默认离线环境中选择只读Agent会提示模型尚未配置，不会调用任何模型。待部署完成，在项目根目录`.env`填写下列字段，再重启服务。完整模板为`.env.local-model.example`。

```dotenv
MODEL_ADAPTER=local
MODEL_CALLS_ENABLED=false
MODEL_NAME=
LOCAL_MODEL_BASE_URL=
LOCAL_MODEL_API_KEY=
LOCAL_MODEL_PROTOCOL=chat_completions
```

URL、Key和模型名按要求留空。准备好服务后填写URL和模型名，并将`MODEL_CALLS_ENABLED`改为`true`；需要鉴权时填写本地Key，无鉴权服务可留空。不要把真实Key提交到Git。`.env`已被忽略，当前默认仍是rules、调用关闭。

`LOCAL_MODEL_BASE_URL`是API基础地址，应按服务实际情况包含`/v1`，不要重复填写`/chat/completions`或`/responses`后缀。协议可选：

|设置|实际请求|预期响应|
|---|---|---|
|`chat_completions`|基础地址 + `/chat/completions`|一个`decide_next`工具调用，或无工具调用时返回严格JSON决策信封|
|`responses`|基础地址 + `/responses`|completed响应中的一个`decide_next`函数调用|

本地协议通过MockTransport验证，具体模型服务器必须支持相应兼容接口；实际兼容性待部署后联调。Chat接口不强制服务器支持`strict`扩展，服务端仍严格校验决策。JSON文本响应不剥离Markdown、不修复、不猜测。

本地Key与`OPENAI_API_KEY`分开，云端Key不会发送到本地URL。不自动回退到云端或脚本决策。本地服务不记供应商API费用，但记录调用、耗时和Token（服务器未提供用量时明确显示未知）；这不代表自托管计算没有成本。

Compose已透传上述本地配置和Agent预算；容器内请填写容器网络可达的模型地址。Docker/PostgreSQL路径仍未在本机实测，不能据此声称容器验收完成。

## 一次任务怎样执行

1. `POST /api/agent/runs`验证身份、页面版本和适配器能力，保存任务并返回202。
2. 单进程后台任务认领QUEUED状态，保存待决策步骤、调用记录和预算预留。
3. 释放数据库事务后调用模型。上下文仅包含用户目标、业务参考时间、工具观察摘要和剩余预算，不包含标准答案、凭据、全部订单ID或备注。
4. 校验模型返回的三个分支之一：调用注册工具、带依据结束、请求澄清。
5. 调用工具时重新验证会话、页面版本、结果集归属/版本/过期和耗时预算；保存实际观察，再次决策。
6. 结束时核对真实结果集、数量及文件；服务端据实际结果生成反馈文本和下载入口。

没有针对“超过10条导出”的业务分支代码。阈值由用户指令交给模型理解，分支由模型读取真实观察后选择；服务端负责权限、预算和完成依据，评价器负责核对任务标准。

## 决策契约

顶层是`{"decision": ...}`，对象额外字段均拒绝：

```json
{"decision":{"kind":"call_tool","tool":"query_orders","arguments":{"filters":{"shipping_city":"上海","waiting_hours_gt":48},"sort":[{"field":"total_amount","direction":"desc"}],"page":1,"page_size":20}}}
```

```json
{"decision":{"kind":"call_tool","tool":"export_orders","arguments":{"result_set_id":"引用成功查询返回的ID","columns":["id","shipping_city","status","total_amount","priority"]}}}
```

```json
{"decision":{"kind":"finish","result_set_id":"引用最近成功查询的ID","total":12,"export_id":"已导出文件的ID或null"}}
```

```json
{"decision":{"kind":"clarify","question":"请指定等待小时数和导出数量阈值。"}}
```

示例中的12仅展示数据类型，不是服务端固定数量。工具输入仍复用现有Filters/Sort、查询与导出服务。未知工具、非法参数、伪造结果集、伪造文件和错误数量均拒绝；工具失败不会变成普通成功观察。

结束必须有本任务最近查询，数量与当前真实集合一致。声称导出必须对应本任务成功工具观察和真实导出记录，且文件归属、结果集、行数匹配；多余文件也不能通过完成校验。没有导出时反馈明确说明未生成文件。

## 持久化与失败语义

迁移0004新增`agent_runs`、`agent_steps`。父Plan进入执行历史，每次模型决策有独立子Plan和现有ModelCall记录；子决策不会挤占网页的任务历史。持久化目标、状态、阶段、当前页面版本、已观察结果集、预算、决策、观察、用量和错误。

查询/导出元数据、页面状态、工具观察与任务当前引用在同一事务提交。工具执行前失败或提交前抛错会回滚；如果数据库已提交但提交响应异常，则保留已经持久化的成功观察，将任务标为TOOL_STATUS_UNCERTAIN并停止，不假报整个任务成功，也不覆盖真实文件记录。

默认限制：6次模型决策、4次工具调用、90秒总耗时、相同规范化工具参数最多执行1次；可通过`AGENT_*`配置。真实模型还受会话调用上限约束。云端适配器继续复用已有持久化预算账本和项目锁，未知费用保留预留额。

每次模型返回、工具执行前后、完成检查及状态查询均检查必要的会话/上下文/时限。用户改变页面时旧任务停止，不覆盖新查询。超时工具提交前会回滚。模型网络有独立超时并受剩余时间约束；不会自动重试或修复失败。

网页通过`GET /api/agent/runs/{id}`轮询，刷新后从本会话任务恢复观察；跨会话或跨租户不能读取。失败任务若前面已生成文件，步骤中保留真实下载入口并标明任务未成功结束。

当前后台执行器是FastAPI进程内BackgroundTasks，不是持久化工作队列。进程中断后不会自动续跑或重放，持久化状态可查询，超过原始deadline后标记失败；阻塞调用不使用强制线程中断，但超时后不接受决策或提交工具效果。澄清后也需发起新任务。

## 评测与复现

24条任务沿用第一步预写的fixture、查询、完整有序ID、页面、文件和终态标准；补齐4条循环场景的预期调用计数。参考数据35单，包含12/9/10/0边界、恰好48/72/192小时、已发货和跨租户干扰。尚未独立人工复核，不是冻结测试集。

```powershell
cd E:\项目经历\llm4web
# 脚本决策替身：验证状态机、工具及评价器；不报告为模型效果
.\.venv\Scripts\python.exe -m scripts.manage agent-eval
# 部署本地模型并配置.env后，显式运行真实评测
.\.venv\Scripts\python.exe -m scripts.manage agent-eval --real
```

真实模式不会读取标准答案生成决策，也不会自动切换为脚本。会运行20条真实决策场景；不存在工具、非法参数、重复决策和启动即超时这4类注入回归单独在脚本模式验证，真实报告中明确NOT_RUN。故障场景有独立标签，不能混成纯自然语言理解准确率。

评价器检查完整查询成员/顺序、条件、当前页/数量/总额、导出次数/对象/字段/逐单元格值、BOM/校验摘要、无多余业务操作、五张业务表不变及实际终态。对重复paid条件和稳定id升序仅接受已知逻辑冗余，不接受任意额外筛选。

输出manifest、逐案JSON、events.jsonl、summary.json/CSV、独立数据库、实际CSV；统计终态成功率、执行正确性、失败类别、调用/Token/耗时/费用。manifest在运行前保存，包含后端、前端、迁移、数据、标准和评价器源码摘要。每案完成保存进度。云端评测跨独立测试库累计已知费用和未知预留，避免每案重置总预算。

网页验收额外提供`frontend`目录下`npm run test:agent`，使用独立18001端口和明确标注的脚本决策测试服务；生产配置无法选择这个测试替身。
