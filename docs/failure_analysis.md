# 开发中发现的问题与边界

下面是工程开发问题，不是虚构的模型失败案例。当前没有模型调用，无法报告模型错误分布或修复收益。

|问题|影响|处理与证据|
|---|---|---|
|消息和侧栏共用 assistant 类名|消息继承侧栏高度，显示异常空白|消息改为 from-assistant；截图复查与消息高度检查通过|
|预览执行后父计划仍待确认|记录与实际已提交操作不一致|预览关联父计划，同步完成/取消；专项状态检查通过|
|上下文继续排序未覆盖原排序|可能显示不符合用户要求的顺序|显式排序传入 refine，稳定附加 id；专项顺序检查通过|
|本机代理干扰浏览器本地就绪检测|测试误判服务启动超时|测试进程回环地址加入 NO_PROXY，3 条流程通过|
|FastAPI 默认 yield 事务退出时机|可能在响应已发送后才发现提交失败|事务依赖改为 function scope，在响应前提交；完整后端测试通过|

已知能力边界：规则解析只覆盖明确句式；多个城市、未知金额比较、含糊操作和复杂复合动作会澄清。未识别的自然语言不应被当成已经执行。当前澄清后用户可重新明确表达，但没有完整的参数槽位补全过程。

SQLite BEGIN IMMEDIATE 将请求事务串行化，适用于本地正确性检查；没有负载测试或生产吞吐量结论。PostgreSQL 配置与兼容代码不能代替实际部署、权限与并发测试。

当前静态标签由开发过程手写，未经过独立人工复核。规则模式对 20 条开发任务通过，既不表示开放自然语言泛化，也不表示大模型效果。后续真实失败分析必须引用真实模型轨迹、原始运行和独立终态检查。
