# v0.5 本机验证记录

本轮验证基于 SQLite、合成订单、明确标注的演示知识文档和模拟模型协议；未调用用户企业模型网关，不报告真实模型成功率。功能和手工测试步骤见 [v0.5说明](features_v0.5.md)。

- 后端：202项通过，4项PostgreSQL检查未运行。新增25项场景覆盖状态追加/替换、保留城市/金额/排序、刷新后的会话上下文、会话隔离、城市去重及零结果、日期条件、知识来源与版本、未知政策拒答、文档归属/路径检查、错误引用拒绝、Agent统计依据、禁止意外导出和兼容接口请求体。
- 浏览器：13条常规流程和4条Agent流程通过。新增3条常规流程实际检查多轮查询成员、刷新恢复、统计不改变列表、知识原文可展开、演示标识、换话题未命中及手机页面无整页横向溢出。
- TypeScript / Vite构建、Ruff和OpenAPI生成契约检查通过。最终构建为`index-DorC-5s7.js`与`index-D94OSHQ9.css`。
- 原只读查询/导出24条脚本回归仍包含在后端评价器测试中。它验证执行器与评价器，不是新增RAG或多轮会话的真实模型评测。
- 没有新增业务表或迁移，没有重置演示库，没有启动或重启用户8000端口的服务。浏览器使用18000/18001独立测试端口和专用实验数据库。

在16单边界fixture的租户A中，用户示例的第一轮返回`12,3,1,10`，追加已发货后返回`12,3,5,1,10`，金额降序且均为上海。全租户城市去重为4个、12条订单；当前上海结果的城市去重为1个。这些是测试fixture的标准值，不是日常1000单演示库的固定结果。

知识示例显示48小时发货和顺丰速运时始终带演示标记、原文和内容版本；询问没有文档的退货政策时返回没有足够依据。真实生成协议由MockTransport验证，正式知识内容、企业网关兼容性、模型引用忠实度与准确率需要用户环境另行验证。

本机详细日志保存在被Git忽略的`runtime/v05-backend-final.log`、`v05-build-final.log`、`v05-browser-final.log`及`v05-agent-browser-final.log`。浏览器过程输出位于`frontend/test-results/v05-workspace-final/`与`v05-agent-final/`。
