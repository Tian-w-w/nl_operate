# 只读 Agent 小版本：第一步工具与标准结果

日期：2026-10-28。

后续状态：本文件记录第一步交付；持久化循环、网页及本地模型接口现已增量完成，见[v0.4说明](features_v0.4_agent.md)。下文20/20和4项NOT_RUN是第一步当时的验收记录。

本里程碑只完成两个注册工具和开发任务标准，不改变现有 `/api/assistant` 单步路径，不接模型决策循环，不新增前端入口。现有查询、导出业务服务保持原样。这里的回放成功率不是 Agent 或真实模型任务成功率。

## 已定义的完成依据

后续小版本以真实查询范围及顺序、页面显示、导出内容和实际终态验收，不以聊天文本验收。模型只能提出调用工具、结束或请求澄清；执行失败先停止，不自动修复、不继续执行。终态应包含成功、失败、等待澄清。

本轮可独立证明：两个工具无需模型可调用；工具成功意味着事务已经提交；失败没有正常输出，也不提交部分结果；结果集、页面及下载内容与预写标准相符。

## 工具契约

实现：`backend/app/tools.py`；输入及通用错误：`backend/app/schemas.py`。`tool_catalog()` 返回两个工具的输入、成功、失败 JSON Schema，没有额外工具或任意 SQL/HTTP 入口。

|工具|模型可见输入|成功输出|
|---|---|---|
|`query_orders`|`filters`、`sort`、`page`、`page_size`|`status=SUCCEEDED`、新 `context_version`、`output` 中的 `result_set_id`、总数、总额、当前页、查询条件和有效期|
|`export_orders`|`result_set_id`、允许的 `columns`|`status=SUCCEEDED`、`context_version`、`output` 中的导出 ID、`state=SUCCEEDED`、行数、字段、校验摘要、真实下载地址|

查询页大小默认20、上限100。筛选与排序复用现有 `Filters`、`Sort`、`QueryRequest`；排序字段仅 id / total_amount / created_at / paid_at，稳定追加 id 升序。等待发货由服务检查 paid、未发货、付款时间严格早于阈值。结果集包含完整集合，输出行数仅是当前页。

导出字段仅 id、shipping_city、status、total_amount、created_at、paid_at、priority、review_status，默认 id/city/status/amount/priority。结果集必须来自本任务成功查询的观察，并且仍是当前结果集、归属当前会话、没有过期或版本变化。导出整个集合并保持查询顺序。

失败格式：

```json
{
  "tool": "export_orders",
  "status": "FAILED",
  "error": {
    "code": "RESULT_EXPIRED",
    "message": "结果集已过期，请重新查询",
    "retryable": false
  }
}
```

失败响应没有 `output`。未知工具返回 UNKNOWN_TOOL，非法或额外参数返回 INVALID_TOOL_ARGUMENTS，未观察结果集返回 RESULT_NOT_OBSERVED；会话、上下文、归属、过期、版本和幂等错误保留业务错误码。意外异常及非法工具输出返回 TOOL_EXECUTION_FAILED，不回传内部异常内容。

## 可信执行上下文

`ToolContext` 仅由服务端创建，不属于模型参数：

- `session_token`：不透明会话凭据，不进入工具 Schema、模型上下文或验收事件。
- `task_id`、`call_id`：由执行器分配，用于稳定生成导出幂等键。
- `expected_context_version`：基于上次已提交观察，由执行器提供。
- `observed_result_set_ids`：本任务成功查询生成的结果集引用集合。

未来运行器必须从持久化的成功观察恢复这些值。当前仅是工具层可信参数，尚未实现持久化 Agent 状态、跨进程恢复或签名凭证。不能把这份上下文开放成可由模型或浏览器自由填入的 HTTP 请求。

每次 `execute_tool` 自行打开短事务，验证会话、页面版本，复用 `service.query_orders` 或 `service.export_orders`，校验输出，然后提交。提交完成才返回成功。模型等待不属于工具执行事务。调用失败不推进上下文、不追加观察引用。

导出相同 task/call 的重试复用同一个幂等键，同键不同字段被拒绝。即使是重试也先检查结果集有效性，因此过期后会停止；此前已经成功生成的文件仍保留。新 call_id 可以创建新导出，防止无意义重复决策和执行的预算检查属于下一步运行器。

“只读”指不修改订单、客户、商品、明细和物流；查询会写结果集和页面状态，也会按现有服务语义取消旧修改预览，导出会写导出记录。

## 验收方式和记录

```powershell
cd E:\项目经历\llm4web
.\.venv\Scripts\python.exe -m pytest tests/test_agent_tools.py -o addopts='' -q
.\.venv\Scripts\python.exe -m evaluation.tool_contracts
```

回放器只按预先写好的参考调用执行，不读取数量决定分支，不解析用户指令，不调用模型。它验证20个工具场景；剩余4个标准明确记录为 NOT_RUN，而不是通过或失败。

检查内容包括完整结果成员和顺序、查询条件、总数和总额、`/api/session` 页面行及数量/总额、上下文版本、导出记录数量及绑定、下载CSV全部字段和值、BOM、校验摘要、五张业务表完全不变，以及无订单操作/修改审计。页面数据源通过API验证，本轮没有新增或声称执行浏览器端到端测试。

输出目录保存 manifest（数据/标准/关键代码摘要）、逐任务结果、逐步工具输入和观察、独立数据库及真实CSV。另有故意错误结果测试，确保错页面顺序/数量/金额、错文件内容、多余导出和业务变更不会被判成功。

本轮没有真实模型调用，没有付费调用，没有修改现有演示库，没有启动或重启已有服务。后续按既定顺序补持久化任务状态、三种决策响应、受限循环、网页和真实模型评测；只有届时才能报告模型选择分支是否成功。
